# North Dry Fruits - Premium Dry Fruits & Nuts Platform

![North Dry Fruits Cover](https://images.unsplash.com/photo-1596769062638-e6ed3f46f496?auto=format&fit=crop&q=80&w=1200)

North Dry Fruits is a premium e-commerce platform dedicated to bringing 100% authentic, sun-dried organic dry fruits and nuts directly from the mountain farmers of Gilgit-Baltistan to your doorstep across Pakistan.

The platform is designed with a modern, responsive UI focused on a seamless shopping experience, alongside a fully-featured CMS admin panel, robust backend, and production-ready SEO optimizations.

## 🚀 Key Features

### Storefront
* **Dynamic Homepage**: Fully customizable promotional strips, carousels, and category showcases built from the admin panel.
* **Shopping Experience**: Filtered product listings, detailed product pages, intuitive cart system, and mobile-friendly sticky action bars.
* **Order Tracking System**: Real-time order tracking timeline via phone number and order ID.
* **AI Chatbot**: Context-aware shopping assistant for product search, pricing, stock checks, and shipping info.
* **SEO & Rich Snippets**: Deeply integrated meta tags (Open Graph, Twitter Cards) and JSON-LD structured data (Product, Organization, BreadcrumbList) for maximum search engine visibility.

### Admin Panel (CMS)
* **Inventory Management**: Create, edit, bulk-import, and soft-delete categories and products.
* **Order Management**: Process orders, verify payment proofs, update statuses with WhatsApp notification links.
* **Homepage Builder**: A dynamic layout builder for injecting and re-ordering promotional banners, carousels, and product grids on the storefront.
* **Store Settings**: Centrally manage contact information, hero imagery, shipping fees, and business policies.
* **Real-time WebSocket Notifications**: Live order alerts with sound chimes in the admin panel.

## 🛠️ Technology Stack

**Frontend (Client)**
* [React JS](https://reactjs.org/) powered by [Vite](https://vitejs.dev/)
* [Tailwind CSS](https://tailwindcss.com/) for utility-first styling
* [React Router DOM](https://reactrouter.com/) for client-side routing
* [React Helmet Async](https://github.com/staylor/react-helmet-async) for dynamic document head management
* [Lucide React](https://lucide.dev/) for crisp, consistent iconography

**Backend (Server)**
* [Node.js](https://nodejs.org/) & [Express.js](https://expressjs.com/) v5
* [MySQL](https://www.mysql.com/) via [mysql2](https://github.com/sidorares/node-mysql2) connection pool
* [Cloudinary](https://cloudinary.com/) for production image storage (local disk fallback for dev)
* [Multer](https://github.com/expressjs/multer) for file upload handling
* **Security**: `helmet`, `cors`, `express-rate-limit`, `xss` payload sanitization

**Deployment Architecture**
* Single-process deployment — Express serves both the API and the built React frontend
* Compatible with **Hostinger Business Web Hosting** (managed MySQL, single Node.js process)

## 📦 Local Installation & Setup

1. **Clone the Repository**
   ```bash
   git clone <your-repository-url>
   cd gbmarket
   ```

2. **Create the MySQL Database**
   ```sql
   -- Using your MySQL client, phpMyAdmin, or terminal:
   CREATE DATABASE IF NOT EXISTS gbmarket CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   ```

3. **Configure Environment**
   ```bash
   cd server
   cp .env.example .env
   # Edit .env with your MySQL credentials (DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME)
   ```

4. **Install & Build**
   ```bash
   # From the repo root:
   cd ..
   npm run build    # Installs deps in client + server, builds the React frontend
   ```

5. **Seed the Database** (optional — loads sample data)
   ```bash
   npm run seed
   ```

6. **Start the Server**
   ```bash
   npm start        # Starts Express on port 5000, serving both API and frontend
   ```

7. **Access the Platform**
   * Storefront: `http://localhost:5000`
   * Admin Login: `http://localhost:5000/admin/login`
   * API Health: `http://localhost:5000/api/health`

### Development Mode (separate processes)

For active frontend development with HMR:
```bash
# Terminal 1 — Backend
cd server && npm run dev

# Terminal 2 — Frontend (Vite dev server with HMR)
cd client && npm run dev
```
* Frontend dev server: `http://localhost:5173`
* API server: `http://localhost:5000`

## 🚦 Before You Deploy (Production Checklist)

Before deploying to a live production environment, verify the following:

- [ ] **MySQL Database**: Created on your hosting provider with credentials configured in `.env`
- [ ] **`JWT_SECRET`**: Set to a real, long random value (server refuses to start with the placeholder)
- [ ] **`ADMIN_USERNAME` / `ADMIN_PASSWORD`**: Set to real values before running `npm run seed` in production
- [ ] **`CLIENT_ORIGIN`**: Set to your real domain (e.g. `https://yourdomain.com`) — the server also auto-allows its own origin for same-origin SPA requests
- [ ] **`CLOUDINARY_*`**: All three env vars set so uploaded images persist in production
- [ ] **`NODE_ENV`**: Set to `production` in your hosting platform's environment variables
- [ ] **`site_url`**: Set correctly in Admin → Settings after first deploy, so `robots.txt` and `sitemap.xml` point to your real domain

> **Note**: `VITE_API_URL` does **not** need to be set for production builds. The client defaults to relative `/api` paths, which work automatically in the single-service deployment since frontend and backend share the same origin.

## 🖼️ Image Storage (Production)

By default, uploaded images are stored temporarily on local disk (fine for development). For production:
* Sign up for a free Cloudinary account and set `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` in `.env`.
* If migrating from local storage to Cloudinary, previously uploaded images will need to be re-uploaded through the admin panel.

## 🗺️ Architectural Highlights

* **Single-Service Deployment**: Express serves both the REST API and the built React SPA from one process — ideal for Hostinger and similar single-process Node.js hosts.
* **MySQL Connection Pool**: 10-connection pool with async/await throughout all route handlers.
* **Dynamic Sitemap**: Driven by `/sitemap.xml` Express route with database-queried product URLs and `lastmod` dates.
* **Bulk Imports**: Support for mass CSV ingestion with relational data integrity validation.
* **Real-time Updates**: WebSocket-powered live order notifications for the admin panel.
